# RAG Evaluation Harness

This document describes the evaluation harness for measuring retrieval quality in X-RAG.

## Overview

The evaluation harness provides tools for:
- **Metrics computation**: Recall@K, Precision@K, Hit Rate@K, MRR, NDCG@K
- **Dataset management**: Loading, saving, and preparing evaluation datasets
- **Evaluation orchestration**: Running retrieval experiments
- **Regression detection**: Comparing evaluation runs to detect quality changes

## Quick Start

### 1. Prepare an Evaluation Dataset

Convert QA pairs (generated by `data/generate-qa-pairs.sh`) into an evaluation dataset:

```bash
# Prepare a single dataset
make eval-prepare DATASET=@JasonLiu/video-transcripts/medium-en MODEL=qwen2.5-7b-instruct-mlx

# Or run the script directly
./data/prepare-eval-dataset.sh @JasonLiu/video-transcripts/medium-en qwen2.5-7b-instruct-mlx
```

This creates: `data/eval/@JasonLiu/video-transcripts/medium-en/qwen2.5-7b-instruct-mlx/dataset.json`

### 2. Run Metrics Tests

```bash
make eval-test-metrics
```

### 3. Use the Evaluation Harness (Python)

```python
from evals import RetrievalEvaluator, load_dataset, compare_runs

# Load dataset
dataset = load_dataset("data/eval/.../dataset.json")

# Run evaluation (requires index_client and embedding_client)
evaluator = RetrievalEvaluator(index_client, embedding_client, top_k=10)
result = evaluator.evaluate(dataset)

# View metrics
print(result.metrics)
# Recall@10: 0.85, Precision@10: 0.12, MRR: 0.72, NDCG@10: 0.78
```

## Metrics

### Retrieval Metrics

| Metric | Description | Range |
|--------|-------------|-------|
| **Recall@K** | Fraction of relevant items retrieved in top K | 0.0 - 1.0 |
| **Precision@K** | Fraction of top K items that are relevant | 0.0 - 1.0 |
| **Hit Rate@K** | 1 if any relevant item in top K, else 0 | 0.0 or 1.0 |
| **MRR** | 1/rank of first relevant item (Mean Reciprocal Rank) | 0.0 - 1.0 |
| **NDCG@K** | Normalized Discounted Cumulative Gain | 0.0 - 1.0 |

### Computing Metrics

```python
from evals.metrics import compute_retrieval_metrics

# Per-query results
retrieved_ids = [["doc1", "doc2", "doc3"], ["doc4", "doc5", "doc6"]]
relevant_ids = [{"doc1"}, {"doc7"}]  # Ground truth

metrics = compute_retrieval_metrics(retrieved_ids, relevant_ids, k=3)
print(metrics)
# RetrievalMetrics(k=3, n=2)
#   Recall@3:    0.5000
#   Precision@3: 0.1667
#   Hit Rate@3:  0.5000
#   MRR:         0.5000
#   NDCG@3:      0.5000
```

## Dataset Format

### EvalDataset JSON Schema

```json
{
  "name": "@JasonLiu/video-transcripts/medium-en/qwen2.5-7b-instruct-mlx",
  "version": "1.0.0",
  "created_at": "2024-12-05T10:00:00Z",
  "chunk_config": {
    "lines_per_chunk": 100,
    "chunk_step": 50
  },
  "samples": [
    {
      "sample_id": "doc_name:qa:7",
      "question": "What are the challenges...?",
      "answer": "The main challenges are...",
      "source_file": "Document Name.txt",
      "chunk_num": 7,
      "line_start": 301,
      "line_end": 400,
      "chunk_id": "doc_name-chunk-7",
      "relevant_chunk_ids": ["doc_name-chunk-7"]
    }
  ],
  "metadata": {
    "total_samples": 150,
    "total_source_files": 20,
    "qa_source_dir": "data/qa/..."
  }
}
```

### EvalSample Fields

| Field | Type | Description |
|-------|------|-------------|
| `sample_id` | string | Unique identifier for this sample |
| `question` | string | The query/question to evaluate |
| `relevant_chunk_ids` | list[str] | Ground truth chunk IDs that should be retrieved |
| `answer` | string? | Optional: Expected answer text |
| `source_file` | string? | Optional: Original source file |
| `chunk_num` | int? | Optional: Chunk number in source |
| `line_start` | int? | Optional: Starting line in source |
| `line_end` | int? | Optional: Ending line in source |
| `chunk_id` | string? | Optional: Primary chunk ID |

## Chunk ID Format

Chunk IDs are **deterministic** based on document ID and chunk index:

```
{doc_id}-chunk-{chunk_index}
```

Examples:
- `better_rag_reducto-chunk-0`
- `my_document-chunk-7`
- `video_transcript-chunk-15`

This matches the format used by the indexer (`src/pipelines/indexing_pipeline.py`).

## Preparing Datasets

### From QA Pairs

The `data/prepare-eval-dataset.sh` script converts QA JSON files to EvalDataset format:

```bash
./data/prepare-eval-dataset.sh <dataset-path> <model-name> [namespace]
```

**Input**: QA files with pattern `{source-file}-qa-{chunk_num}.json`
```json
{"question": "...", "answer": "..."}
```

**Output**: Single EvalDataset JSON with computed chunk IDs

### Chunk Number to Line Range Mapping

QA files use chunk numbers that map to line ranges:
- `LINES_PER_CHUNK = 100`
- `CHUNK_STEP = 50` (50% overlap)

| Chunk | Line Start | Line End |
|-------|------------|----------|
| 0 | 1 | 100 |
| 1 | 51 | 150 |
| 2 | 101 | 200 |
| ... | ... | ... |

Formula: `line_start = chunk_num * chunk_step + 1`

## Running Evaluations

### Basic Evaluation

```python
from evals import RetrievalEvaluator, load_dataset

dataset = load_dataset("data/eval/.../dataset.json")

# Create evaluator with your index and embedding clients
evaluator = RetrievalEvaluator(
    index_client=my_index_client,      # Implements IndexClient protocol
    embedding_client=my_embedding_client,  # Implements EmbeddingClient protocol
    collection="documents",
    top_k=10,
)

# Run evaluation
result = evaluator.evaluate(dataset, run_id="baseline-v1")

# Access metrics
print(f"Recall@10: {result.metrics.recall_at_k:.4f}")
print(f"MRR: {result.metrics.mrr:.4f}")
print(f"NDCG@10: {result.metrics.ndcg_at_k:.4f}")
```

### Saving and Loading Results

```python
from evals.harness import save_eval_run, load_eval_run

# Save result
save_eval_run(result, "evals/reports/baseline-v1.json")

# Load result
loaded = load_eval_run("evals/reports/baseline-v1.json")
```

## Comparing Runs

Detect regressions by comparing evaluation runs:

```python
from evals import compare_runs

baseline = load_eval_run("evals/reports/baseline-v1.json")
current = load_eval_run("evals/reports/experiment-v2.json")

comparison = compare_runs(baseline, current, regression_threshold=5.0)

print(comparison)
# Comparison: baseline-v1 → experiment-v2
# Dataset: my-dataset
# Regression threshold: 5.0%
#
# Metric Changes:
#   recall_at_k: 0.8500 → 0.8200 (↓ -0.0300, -3.5%)
#   precision_at_k: 0.1200 → 0.1150 (↓ -0.0050, -4.2%)
#   ...
#
# → No significant changes

if comparison.has_regression:
    print("REGRESSION DETECTED!")
    for metric in comparison.regressed_metrics:
        print(f"  {metric.metric_name}: {metric.relative_change_percent:.1f}%")
```

## Implementation Notes

### Deterministic Chunk IDs

Chunk IDs are deterministic (not random UUIDs) to enable:
- Reproducible evaluation across runs
- Ground truth mapping from QA pairs
- Consistent chunk identification

Changed in `src/pipelines/indexing_pipeline.py`:
```python
# Before: self.chunk_id = str(uuid.uuid4())
# After:
self.chunk_id = f"{doc_id}-chunk-{chunk_index}"
```

### Frozen Configurations

All configuration classes use `frozen=True` to prevent mutation:
```python
model_config = SettingsConfigDict(
    ...,
    frozen=True,  # Immutable configs for reproducible evaluation
)
```

### Protocol-Based Design

The evaluation harness uses Protocol classes for dependency injection:
- `EmbeddingClient` - for query embedding
- `IndexClient` - for vector search

This allows testing with mock implementations or embedded Weaviate.

## Troubleshooting

### "ModuleNotFoundError: No module named 'evals'"

The `evals` package requires the project root in Python path. Use:
```bash
uv run python -m evals.datasets.prepare ...  # Correct
```

Or run through Makefile targets which handle the path automatically.

### QA Files with Invalid JSON

Some QA files may have invalid JSON (escape characters, control characters). The prepare script logs warnings and skips invalid files:
```
Could not load .../file-qa-1.json: Invalid \escape: line 1 column 117
Parsed 738 QA pairs from 53 source files  # Out of 749 files
```

### Empty Dataset After Preparation

If no samples are created, check:
1. QA files exist in `data/qa/<dataset>/<model>/`
2. Filenames match pattern `{source}-qa-{chunk_num}.json`
3. JSON files contain `question` and `answer` fields
